## 6. Public and internal content risk

| Risk | Finding | Action |

| Pages publishes the whole repository | High: any internal file committed becomes public | Publish a built public bundle (`dist/`) instead of the repository root |

| Hiding internal pages with CSS, JavaScript or the password | Not acceptable | Internal pages are absent from the public bundle; a scanner fails the build if internal terms appear |
| Client-identifying details in the source deck (named regulators combined with real requests and figures) | Medium | Generalise in the public build; verbatim only in the internal build |
